# 内容模型（文章与项目）

> 依据 2026-09-29 的确认：文章与项目都可能有图片与外部链接、都有一句话简介／标签／日期；**多标签同时筛选**；不做置顶、不做计划发布。

---

## 1. 安全模型（先澄清，因为它决定了评论怎么做）

**结论：除了你自己的 GitHub 账号，没有任何人能改这个网站。** 这不是靠防护做到的，而是结构决定的——

- 线上站点是**构建产物**：GitHub Pages 只会把仓库内容编译出的静态文件发出去，**没有后台、没有登录入口、没有数据库、没有任何写入接口**。访客能做的只有下载网页。
- 唯一的写入路径是 **Git 提交**，而只有拥有仓库写权限的账号能提交 —— 也就是你自己。
- 所以真正的风险只有四条，对应四个措施：

| 风险 | 措施 |
| --- | --- |
| 你的 GitHub 账号被盗 | **开 2FA（优先用 passkey）**；这是整个体系里唯一的"钥匙"，务必唯一且强 |
| 依赖里混进恶意代码 | 依赖最小化 + 锁定版本 + Dependabot + CI 只在全绿时合并 |
| 第三方脚本被投毒（评论/统计） | 只选知名服务；懒加载；每个都在 `01-design-spec.md` 登记体积与来源 |
| Actions 里的密钥泄漏 | 密钥只放 Secrets；用最小权限的只读 `GITHUB_TOKEN`；不在日志里打印 |

### 评论会不会破坏这个安全模型？不会

用 **giscus**：评论存在你仓库的 **GitHub Discussions** 里，评论者用**他们自己的** GitHub 账号登录。

- 你**不需要自己写账号系统、不需要数据库、不需要处理密码**——这是安全上更优的选择，不是妥协。
- giscus 只通过自己的 GitHub App 读写 **Discussions**，**没有权限改你的代码或 Pages 配置**。
- 你还能随时删除任意评论、关闭讨论，或一键关掉整个评论区。
- **放置范围（已确认）**：**文章详情页与项目详情页都放评论区**；两页都保持"滚动到评论区才加载"。

> **不推荐**为了"让没有 GitHub 账号的人也能评论"去自建后端：那才需要真正的账号体系、数据库、防刷与合规，安全负担会成倍上升。首版用 giscus，覆盖绝大多数技术读者。

## 2. 文章（posts）

```yaml
---
title: 用 Rust 重写日志管道：吞吐提升 7 倍
summary: 一句话简介，出现在列表卡片与 RSS 里。      # 必填，1 行
pubDate: 2026-09-18
updatedDate: 2026-09-24        # 可选
tags: [rust, performance]      # 必填，可多个
cover: ./cover.png             # 可选，列表卡片首图
draft: false                   # 可选，true 时只在本地可见
---
```

正文用 Markdown，支持：

- **图片**：`![说明](./images/xxx.png)`；构建期自动输出 AVIF/WebP 多尺寸，并强制要求有 alt 文本（无障碍红线）。
- **链接**：普通 Markdown 链接即可；站外链接自动加 `target="_blank"` + `rel="noopener noreferrer"`。
- **代码块**：构建期高亮，首屏零成本；自动附复制按钮。

**不做**：置顶、计划发布（按确认）。

## 3. 项目（projects）

```yaml
---
title: 分布式日志聚合管道
summary: 一句话简介。                            # 必填，1 行
tags: [rust, kafka]                             # 必填，可多个
date: 2025.10                                    # 必填
cover: ./cover.png                              # 可选，列表缩略图
repo: https://github.com/<user>/<repo>          # 常见：GitHub 仓库
video: https://www.bilibili.com/video/BVxxxx    # 可选：B 站等视频链接
links:                                          # 可选：任意其他链接
  - label: 在线演示
    url: https://…
featured: true                                  # 可选：进首页精选
---
```

正文里可以放**更多图片**（架构图、界面截图）与详细说明。

外链规则：全部渲染成 `<a target="_blank" rel="noopener noreferrer">`，键盘与屏幕阅读器可用；视频链接在卡片上以等宽小字标注类型（`VIDEO` / `REPO` / `DEMO`），不加载第三方播放器（点出去看）。

> star 数等动态信息**在构建期抓取**并固化成 JSON；不在浏览器里调 GitHub API。

## 4. 多标签筛选（文章页与项目页共用一套语义）

**交互**：标签是**多选**开关（不是单选）。点第一个是筛选，再点第二个是**在结果里继续缩小范围**；再点一次取消该项；`全部` 一键清空所有已选标签。

**语义（已确认：OR + 按匹配度排序）**

1. **筛选用 OR**：只要命中**任意一个**已选标签就会显示。选得越多，结果越宽（适合"逛"）。
2. **排序用匹配度**：命中标签**数量多**的排前面。例如同时选 `rust` + `performance`：
   - 两个标签都有的条目排最前；
   - 只有 `rust` 或只有 `performance` 的排在后面；
   - 并列时按**日期倒序**（新→旧），再并列则按标题稳定排序，保证每次渲染顺序一致。
3. **计数**：标签后面的数字按**当前选择**动态重算，即"点一下会得到几条"。
4. **空结果**：不出现空白页，复用既有空状态文案；`全部` 一键清空所有已选标签。
5. **不改变数据**：排序只影响展示顺序，不改动 Markdown 里的任何内容；未选任何标签时恢复默认顺序（日期倒序）。

> 交互上建议：选中标签时，列表**用一次过渡重排**（不是瞬间跳变），让"前面多出来的几条"能被看见；开启"减少动态效果"时直接切换。

**实现要点**：当前原型里两个页面都还是"单选"（`activeTag` / `PROJ.stack` 是字符串），**尚未改成 OR 多选 + 匹配度排序**。改动点：

1. 状态由字符串改为数组（`activeTags = []`）；
2. 匹配改为"任一命中即显示"，并**记录每条命中的标签数量**；
3. 排序：命中数降序 → 日期降序 → 标题；
4. UI 允许同时多个 `is-on` 与 `aria-pressed="true"`；
5. 标签计数按当前选择重算；
6. 项目页需与"每页 N 个"的分页联动：**重排后页码归零**（否则会停在一个不存在的页）。

这部分属于原型代码改动，可按需执行，或交由搭建会话按本节实现。

## 6. 已确认的交付与范围（2026-09-29）

| 事项 | 结论 |
| --- | --- |
| **部署由谁做** | **你自己操作**。搭建会话只负责把仓库与配置准备好并本地跑通；上线时按 `02-build-and-deploy.md` §7.5 的六步走，届时会给一份针对当时状态的实操作业 |
| 首版页面范围 | 首页、文章列表、文章详情、项目列表、项目详情、关于、404。归档 / Now / Uses / 友链放二期 |
| RSS | **输出全文**（已确认）；界面上不放入口，仅构建期输出 `/rss.xml` + `<head>` 自动发现标记 |
| 图片存放 | **直接进仓库**（构建期压缩成 AVIF/WebP 多尺寸）；未来若放大批量高清图再考虑图床 |
| 评论范围 | 文章详情页 + 项目详情页，均滚动到评论区才加载 |
| 代码高亮 | **与 VS Code 默认主题一致**：暗色用 `dark-plus`（VS Code 的 Dark+ 默认暗色），亮色用 `light-plus`（Light+）。Shiki 内置这两个主题，构建期直接指定即可。代码块底色仍用站点的纯黑面板，只取主题的 token 配色 |
| 图片点击 | 全屏灯箱（原生脚本，左右切换 + Esc 关闭） |
| **GitHub 用户名** | **Jokezero** —— 仓库名用 `jokezero.github.io`，站点地址即 `https://jokezero.github.io/`（用户名在 URL 中不区分大小写） |
| 统计服务 | **可随时更换**：它只是一个脚本片段，换服务 = 换一行配置（放在 `src/config/site.ts` 的开关里）；注意旧服务的数据不会迁移，如需对比可短暂并行运行 |
| RSS 是否需要服务 | **不需要任何服务端或账号**。RSS 只是构建期生成的一个静态文件 `/rss.xml`；"订阅"发生在读者那一端——他们把地址粘进自己的阅读器（Feedly / Inoreader / NetNewsWire / Follow），由阅读器定时来取。你不需要运行任何东西 |
| RSS 入口 | **可以不提供任何可见入口**（已确认）。做法：界面上不放 RSS 按钮或链接；仍建议在 `<head>` 保留一行自动发现标记、并在构建期输出 `/rss.xml`——两者都不可见、零成本，但懂得读者把网址丢进阅读器时能自己找到源。若连文件也不想生成，把 RSS 集成从构建配置里移除即可 |
| **站点名** | **zeroweb** —— 出现在顶栏标识、网页标题、OG 分享图与页脚；改名只动 `src/config/site.ts` 一处 |
| 自定义域名 | **暂时不需要**。用 GitHub 默认地址 `https://jokezero.github.io/` 即可：免费、无需购买、无需配 DNS、HTTPS 自动开启。以后想要独立域名随时可以加，属于非破坏性改动（改 `site` 配置 + 填域名 + 配 DNS） |
