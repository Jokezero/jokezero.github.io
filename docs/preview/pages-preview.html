用 Rust 重写日志管道：吞吐提升 7 倍

把 40 台机器的日志收敛进一条管道，端到端延迟从 5.8 秒降到 800 毫秒。

旧管道是典型的"边写边丢"：每台机器各自往磁盘追加，再靠一个每 30 秒扫一次的搬运进程汇总。日志量涨到每天 1.2 TB 之后，搬运进程成了瓶颈。

先说结论

重写的核心只有三点：把轮询换成推送、把每行一次系统调用换成批量追加、把压缩从写完后做换成边写边做。实测端到端延迟从 5.8 秒降到 800 毫秒，P99 抖动也从 3 秒收敛到 200 毫秒以内。

RUST复制
// 批量追加：攒够 64 行或 20ms 再落盘
let batch = writer.batch().max_lines(64).max_wait_ms(20);
batch.append(line)?;
延迟不是"平均下来还行"就够的。日志管道的价值在于出故障那一刻它有没有把现场留下来。

踩过的坑

  • 批量越大吞吐越高，但故障时丢的就越多——最后定在 64 行 / 20ms 这个折中。
  • 压缩必须在下游完成，否则写入路径的 CPU 会成为新瓶颈。

背景

做了什么
