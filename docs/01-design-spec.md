## 1. 项目定位与目标

### 1.1 一句话定位

一个**介于自我介绍与个人博客之间**的个人网站：访客在 3 秒内知道"我是谁、我在做什么、我擅长什么"，并且立刻感受到作者的工程能力与审美水准；愿意留下来阅读技术内容，并能在长期（3-5 年）持续更新，而不需要重写。

### 1.2 三条硬约束与对应策略

| 约束 | 潜在冲突 | 采用策略 |
| --- | --- | --- |
| 部署到 GitHub（静态托管，无后端） | 评论、搜索、统计、动态数据都"需要服务端" | 全部改用**构建期生成**或**纯客户端静态方案**（见 §5.4） |
| 极致轻量、加载要快 | "炫技"通常意味着大动效，体积与性能双输 | **渐进增强 + 分级降级**：招牌效果延迟加载，弱设备自动降级为静态图（见 §4.4、§6） |
| 硬核、有"炫技"感 | 炫技常牺牲可访问性与可读性 | 把"硬核"建立在**排版、信息密度、动效品质**上，而不是"重"上；用性能预算和 CI 门禁强制约束（见 §6.3、§7） |
| 长期维护 | 技术债、依赖腐化、内容流程复杂 | 依赖最小化、内容与代码分离、文档与 ADR 化、CI 回归（见 §10） |

### 1.3 成功标准（可验收）

1. 首屏在中端手机 + 4G 网络下 **LCP < 1.5s**，Lighthouse 性能分 **≥ 95**（首页含招牌动效时 ≥ 90）。
2. 首页首屏总下载量 **< 250 KB**（gzip，含字体与招牌动效）。
3. 弱网/低端设备/`prefers-reduced-motion`/开启省流量时，**功能与可读性零损失**，仅动效降级。
4. 发布一篇新文章：写一个 Markdown 文件 → 提交 → 自动上线，**不超过 2 分钟人工操作**。
5. 键盘可完整操作全站（导航、搜索、命令面板、文章内锚点），对比度符合 WCAG AA。
6. 站点在一年后仍未更新依赖的情况下**仍可构建、仍可访问**（依赖锁定 + 零外部运行时依赖）。

| `/404` | 404 | 品牌感 + 救援导航 | 终端风格报错、返回入口 | ✅ |
| `/rss.xml`、`/sitemap-index.xml`、`/robots.txt` | 机器可读 | SEO/订阅 | 构建期生成 | ✅ |

### 2.2 导航结构

- **顶栏（全局）**：Logo/站点名 · 首页 · 文章 · 项目 · 关于 · 搜索（`⌘K`）· 主题切换 · RSS
- **移动端**：折叠为菜单面板，但**保留搜索与主题切换的一级可见性**。
- **页脚**：联系方式、社交链接、版权、`Built with ...`、最后构建时间、`RSS`。
- **快捷入口**：全局键盘快捷键 `⌘K`/`Ctrl+K` 打开命令面板（跳转页面、搜索文章、切换主题、复制邮箱）。

### 2.3 页面优先级（首版范围）

P0（首版必须有）：首页、关于、文章列表、文章详情、项目列表、标签页、404、RSS/Sitemap。
P1（上线后 1-2 个月内补齐）：归档、项目详情、Now、Uses、友链。
原则：**先把骨架、内容管道、性能门禁做扎实，再堆视觉**。

## 3. 内容模型

### 3.1 内容集合（Astro Content Collections，zod 校验）

| 集合 | 位置 | 用途 |
| --- | --- | --- |
| `posts` | `src/content/posts/*.md(x)` | 博客文章 |
| `projects` | `src/content/projects/*.md` | 项目条目 |
| `pages` | `src/content/pages/*.mdx` | about / now / uses 等静态页 |
| `notes`（可选） | `src/content/notes/*.md` | 短文/微博式碎念 |

### 3.2 `posts` frontmatter 草案

```yaml
---
title: "标题"
description: "一句话摘要，用于列表卡片与 SEO"
pubDate: 2026-10-01
updatedDate: 2026-10-05      # 可选
tags: [astro, performance]
series: "从零搭建个人站"      # 可选，系列文章
draft: false                  # true 时仅在本地可见
cover: "./cover.png"          # 可选，会自动生成响应式多尺寸
lang: zh                      # 预留多语言
featured: true                # 是否进入首页精选
comments: true                # 单篇可关闭评论
---
```

规则：

- **字段全部经 zod 校验**，构建期报错而不是运行时白屏。
- `readingTime`、`toc`、`related` 由构建期自动计算，作者不手写。
- 支持**计划发布**：`pubDate` 在未来时，构建期自动排除（配合每日定时构建，见 §10.3）。

### 3.3 内容与代码分离原则

- 想新增内容，**只需新增一个 Markdown 文件**，不需要碰任何组件或配置。
- 站点的可变信息（站点名、导航、社交链接、功能开关）集中在 **`src/config/site.ts`** 单一文件，其他文件不得硬编码。
- 功能开关示例：

```ts
export const features = {
  heroEffect: "shader",     // "shader" | "static"
  commandPalette: true,
  comments: true,
  search: true,
  analytics: true,
};
```

一句话关掉某个"炫技"功能即可回退，这对长期维护是关键的保险丝。

## 4. 视觉与交互设计语言

### 4.1 五条设计原则

1. **信息密度即质感**：硬核感来自精确的网格、对齐、字号层级、数据细节（构建时间、字节数、状态灯），而非堆砌特效。
2. **纯黑为底，线条为主**：底色是纯黑 `#000000`；画面的全部内容由细线构成——排版是线（发丝分隔线、几何网格），视觉也是线（代码绘制的线条动画）。颜色近乎只有黑、白、灰三档，强调色最多出现一次。
3. **动效要有理由**：每个动效必须回答"它帮助用户理解了什么"。装饰性动效必须可关。
4. **一秒进入内容**：任何情况下，正文内容不等待动效加载完成。
5. **工程痕迹是美学**：等宽字体、行号、网格线、坐标标注、终端光标——这些"工程感的细节"本身就是风格，且几乎零性能成本。

### 4.2 设计令牌（CSS 变量 + Tailwind `@theme`）

所有颜色/字号/间距/动效时长以 CSS 变量定义在 `src/styles/tokens.css`，Tailwind v4 通过 `@theme` 映射为工具类。

| 类别 | 令牌 | 说明 |
| --- | --- | --- |
| 背景 | `--bg-0/1/2` | `--bg-0` 固定为纯黑 `#000000`；1 = 极淡的浮层，2 = 悬浮层（均为黑色微调，不使用渐变） |
| 前景 | `--fg-0/1/2` | 主文本（近白）/ 次要文本（中灰）/ 弱化文本（深灰），对比度递减但正文均 ≥ 4.5:1 |
| 线条 | `--line-0/1/2` | 画面主角：`rgba(255,255,255,.06/.14/.28)` 三档透明度，用于动画线、发丝分隔线、边框 |
| 强调 | `--accent` | **至多一个**，仅用于链接悬停、当前项、光标等极小的交互点；禁止用于正文与大面积填充 |
| 状态 | `--ok`、`--warn`、`--err` | 状态灯、提示 |
| 字体 | `--font-mono`、`--font-sans`、`--font-display` | 见 §4.3 |
| 尺度 | `--step--1 … --step-6` | 模数化字号，clamp() 实现流体排版 |
| 间距 | `--space-1 … --space-12` | 8px 基准网格 |
| 动效 | `--dur-fast/base/slow`（120/220/400ms）、`--ease-out/spring` | 统一节奏感 |

**主题**：默认纯黑；亮色主题为可选（通过 `data-theme` 属性切换 + `localStorage` 记忆 + `prefers-color-scheme` 跟随）。亮色不是"反转"，而是把同一套线条语言搬到白底上：底色纯白、线条转黑、透明度档位重新校准。**禁止**使用玻璃拟态、彩色渐变、投影、发光边框等"廉价科技感"装饰。

### 4.3 字体策略（轻量化的关键决策）

| 用途 | 方案 | 理由 |
| --- | --- | --- |
| 拉丁等宽（标题、代码、UI） | **自托管 1 款**，如 JetBrains Mono / IBM Plex Mono，仅拉丁字符子集，woff2 | 体积可控（10-25 KB/字重） |
| 中文正文 | **系统字体栈**：`system-ui, "PingFang SC", "Microsoft YaHei", "Noto Sans CJK SC", sans-serif` | 中文字体文件动辄 3-8 MB，子集化后仍难控制；系统栈零下载、渲染最稳 |
| 中文标题 | 复用中文系统栈 + 字重与字距调整营造质感 | 避免为了"好看"付出几百 KB 的代价 |

硬性规则：

- 最多 **2 个自托管字体文件**、最多 2 个字重，总体积 ≤ 120 KB。
- 全部 `font-display: swap` + `<link rel="preload">` 仅预加载首屏必需的那一个文件。
- 禁止使用图标字体；图标一律内联 SVG sprite。

### 4.4 招牌效果分级（"炫技"的具体落点）

为了让"炫技"与"轻量"共存，把动效分为三级，按页面与设备能力挂载：

| 级别 | 触发条件 | 效果示例 | 成本 |
| --- | --- | --- | --- |
| **Tier A（全站，默认开启）** | 纯 CSS/SVG，无 JS 依赖 | 网格背景、扫描线纹理、悬停光晕、链接下划线动画、卡片边框描边、焦点环 | ~0 KB JS |
| **Tier B（首页 Hero，延迟加载）** | 首屏渲染完成后 `requestIdleCallback` + 能力检测通过 | 代码绘制的线条动画：自绘几何线 / 波动线场 / 连线网络 / 流动线束 / 三维线框（Canvas 2D 或 SVG，无第三方库） | 2-6 KB JS（详见 §4.5） |
| **Tier C（可选彩蛋，按需触发）** | 用户主动操作（如输入命令、点开某入口） | 终端式彩蛋交互、ASCII 动画、页面切换过渡、音效 | 按需 chunk，不参与首屏 |

**能力检测与降级（必须实现）**：

- `prefers-reduced-motion: reduce` → 关闭所有自动动画，仅保留静态图案（并提供"仍然播放"的手动开关）。
- `navigator.connection.saveData` 或 `effectiveType` 为 2g/3g → 跳过 Tier B。
- 无 `CanvasRenderingContext2D` / 无 `requestAnimationFrame` / 帧率持续低于阈值 → 自动切静态帧（同一帧渲染一次后停住）。
- 移动端小屏或低端设备 → 降低线数、减少粒子、`devicePixelRatio` 上限 1.5 或直接静态帧。
- 页面失焦（`visibilitychange`）→ 暂停渲染循环，省电。

### 4.5 视觉方向：**方向 E · 极简线条**（已确定）

> 状态：**已确定**。此前的四个候选方向（终端净化 / 赛博霓虹 / 冷金属工业 / 数据深海）经用户评审后全部否决，原因统一为"不是想要的画面"。以下为最终方向，后续视觉工作全部在此框架内进行。

**核心定义（四条，不可偏离）**

1. **背景纯黑**：`#000000`，不使用深灰、深蓝、渐变、噪点纹理来"打底"。
2. **画面主体是代码绘制的线条动画**：细线、单色、低透明度、运动缓慢且连续；线条由数学公式实时生成（正弦场、流场、三维投影、描边自绘），而不是播放视频或 GIF。
3. **页面极简**：一屏内可见信息块不超过 4 个；大量留白；除线条外不添加任何装饰元素；文字克制、层级靠字号与灰度而非颜色区分。
4. **技术力来自"线"本身**：线条的数学建模、运动的呼吸感、以及排版与动画的精确对位，构成全部的技术展示。不靠素材堆砌、不靠特效数量。

**线条动画形态候选**（五选一作为首页招牌，其余可复用为局部彩蛋；待用户在 `03-open-questions.md` B3 确认）

| 代号 | 形态 | 技术实现 | 预估体积 | 气质 |
| --- | --- | --- | --- | --- |
| **E1 自绘几何线** | 几何构图沿路径逐段"画"出来，画完停留、淡出、循环 | Canvas 2D 路径长度累积 + 描边 | ≈ 3 KB | 最"极简艺术品"，克制、有仪式感 |
| **E2 波动线场** | 数十条平行细线随正弦场起伏，形成地形/声波感 | Canvas 2D 正弦线场 | ≈ 2 KB | 平静、有呼吸感，最耐看 |
| **E3 连线网络** | 稀疏节点缓慢漂移，距离近时自动连线 | Canvas 2D 邻近连线 | ≈ 2 KB | 经典"数据/网络"隐喻，实现最稳 |
| **E4 流动线束** | 大量粒子沿流场运动，拖出细密流线 | Canvas 2D 流场 + 拖尾 | ≈ 3 KB | 最有机、最有生命感，需要降级策略 |
| **E5 三维线框** | 透视投影的线框地形/物体缓慢起伏 | Canvas 2D 三维投影（**不需要 GPU/WebGL**） | ≈ 5 KB | 最硬核，技术感最强 |
| **E6 制图线** | 斜向制图辅助线 + 逐段画出的三角线稿 + 顶点圆点 + 缓慢旋转的虚线印章 | Canvas 2D 描边 | ≈ 4 KB | 最贴近 jiejoe 的"工程图纸"气质 |
| **E7 原子结构** | 三条互成 60° 的椭圆轨道（经典原子图标）+ 每圈一个带短拖尾的电子 + 中心原子核 | Canvas 2D 椭圆参数化 | ≈ 3 KB | **文章页（ARCHIVE）的整页背景**，常亮、铺满视口 |
| **E8 三体运动** | **真实牛顿引力模拟，混沌解**：质量 3/4/5 的三颗恒星从静止的 3-4-5 直角三角形顶点开始自由坍缩，反复近距离交会、互相甩动，轨道永不重复，最终有恒星被彻底抛出、系统崩解并进入下一轮。三颗恒星以径向渐变的**发光光源点**呈现，配短拖尾 | 速度 Verlet 积分（dt = 1/1000，软化长度 0.08，G = 1） | ≈ 7 KB | **首页背景**；技术力最硬的一项——画面是算出来的，不是播出来的；对应《三体》中乱纪元的混沌 |
| **E11 线框球** | 经纬网格球体绕倾斜轴自转，球面上有 7 个缓慢呼吸的数据点；按深度分段着色形成体积感 | 球坐标 → 旋转 → 透视投影；每条环切成 8 段按平均景深着色 | ≈ 3 KB | **项目页的整页背景**。**洛伦兹吸引子与等高线地形都因视觉效果不理想被换掉**（前者像一团乱线，后者太平） |
| **E12 双摆** | 两个质点由刚性杆相连，末端轨迹是混沌花瓣；摆杆与两个质点作为前景实体 | **四阶龙格-库塔**（dt = 1/600），轨迹缓存 700 点 | ≈ 4 KB | **关于页的整页背景**（常亮、铺满视口）；实测 120 秒模拟能量零漂移 |
| **E13 鼠标视差** | 指针在页面内移动时，当前页面的整套模拟（三体 / 原子 / 等高线 / 双摆）跟随指针平移，横向上限约 ±27px、纵向上限约 ±12px；指针离开后约 1 秒内平滑归零 | 在绘制阶段给模拟落点叠加偏移（`drift()`），**不改动模拟的状态、轨迹与积分** | ≈ 0 KB | 满足"整个模拟随鼠标移动，且不影响模拟本身"的要求 |
| **E10 滚动特效** | 顶部 1px 进度线随滚动增长；Hero 文案随滚动向上位移并淡出；画布向下做 5% 视差；背景亮度随滚动降到 22%；Hero 底部的 `SCROLL` 提示（1px 竖线 + 等宽字母）在滚动后消失 | CSS 自定义属性 `--sy` / `--sp` 由 JS 在 `requestAnimationFrame` 内写入，动画全部由 CSS 完成 | ≈ 0 KB | 与 wodniack 的 `--scroll-progress` 驱动方式一致：JS 只灌变量，样式侧做插值 |
| **E9 页面切换动效** | **幕布 + 逐字飞出**：一块停在画面上方的整屏幕布（黑底 + 44px 间隔的 1px 横线纹理 + 下缘发丝线）向下扫过并继续向下离开；同时离开页标题按 `index % 4` 朝四个方向逐字飞出，新页标题从反方向逐字归位；幕布中央显示随目标页变化的等宽文案（`LOADING · ARCHIVE` 等）。首次进入另有进场遮罩 | 纯 CSS `transform`（幕布）+ 逐字 `translate3d`；JS 只切 `is-cover` / `is-pass` / `is-transitioning` 类 | ≈ 0 KB | 逐字飞出取自 wodniack.dev，常驻遮罩取自 jiejoe.com，系统式文案取自 cosmicbroth.com；详见 `04-reference-motion-study.md` |

> **最终组合（已确定）**：**每个页面有自己的背景模拟，但风格完全统一**——均为一根细线、单色、低亮度、带拖尾的实时计算结果。首页 = 三体运动，文章页 = 原子结构，项目页 = 洛伦兹吸引子，关于页 = 双摆。页面之间用 **E9 页面切换动效**过渡，滚动叠加 **E10 滚动特效**，鼠标移动时整套模拟做视差位移（E13）。

> **风格统一原则（2026-09-29 确认）**："所有的风格都按照第一页对齐"指的是**风格规范**（纯黑底、单色细线、等宽微标签、无框排版、低亮度背景），**不是**要求所有页面共用同一张背景。背景可按页面更换，但必须落在同一套规范内：同为实时计算、同为细线、亮度不高于正文、不添加色彩与发光色块。今后新增页面一律遵循此规范。

> **背景的定位与已纠偏的做法**：背景低亮度、短拖尾、只做极轻微视差，亮度与运动幅度都明显低于正文。三体曾作为前景主角（配 COM 标记、引力连线、能量读数、场景切换器）、曾与原子叠加、也曾被铺满整页；原子做过"三条 Bohr 环"与"16 条轨道三维轨道球"两个更复杂的版本。以上做法均已废弃。

> **三体的正确形态**：必须是**混沌**的，不是规则循环的轨迹（曾误用"8 字舞"周期解，已废弃）。判断标准：三个天体的运动不可预测、轨道不重复、会出现近距离交会，并最终发生一次"系统崩解"——有恒星被抛出。原型中每约 40 秒崩解一次，淡出后以 ±3% 扰动重新播种，因此**每一轮的轨迹都不相同**。

> **已按要求移除**：等宽 0/1 字符场、横贯画面的波动线、跟随光标的制图十字（瞄准镜）、指针与装置之间的连线。这些相关代码已从原型中删除，**实现阶段不得重新引入**。

**推荐组合**：首页 Hero 用 **E1 或 E2**（极简、耐看、与正文争夺注意力最少），在滚动到某个节点或项目页时用 **E5** 做一次"技术力爆发"。全部为纯 JS 计算 + Canvas 2D 描边，**不引入 three.js 等任何图形库**。

**由参考推导出的页面骨架**（与 `docs/preview/prototype.html` 一致）

1. 顶栏：左侧三角形线稿标记 + 等宽站点名；中部次级灰导航（可点击，触发页面切换）。**右上角不放任何按钮**——`⌘K` 与订阅按钮已按要求移除。
2. **两块画布，各管一段**（这是 2026-09-29 修复后确定的结构）：
   - `#scene`：位于**首屏内部**（`position: absolute`），绘制首页 / 项目页 / 关于页的背景模拟（三体 / 洛伦兹 / 双摆）。它随首屏一起滚动，并随滚动压暗——符合"三体是第一页的背景"。
   - `#listScene`：位于**文章页内部**（`position: fixed` 铺满视口），只绘制文章页的原子结构，作为**整页背景**常亮。文章页隐藏时（父节点 `display: none`）该画布随之不渲染。

   内容层统一 `position: relative; z-index: 2`。**这条不能省**：固定定位的背景层（`z-index: 0`）在绘制顺序上高于普通流的静态内容，不加 z-index 会把顶栏、列表、页脚全部盖住。

   > **重要约束：背景不抢戏。** 背景低亮度、短拖尾、只做极轻微视差；不在背景之上再叠第二个"独立视觉主体"。
3. Hero 左栏：等宽全大写 kicker → 两行标题（clamp 30–50px、左对齐）→ 一段说明文字 → 两个胶囊按钮 → 一行等宽说明 → 一行等宽元信息。底部中央是 `SCROLL` 提示（1px 竖线 + 等宽字母）。
4. **页面切换（E9）**：标题逐字朝四个方向飞出 → 幕布自上而下扫过（覆盖 520ms）→ 紧接着继续向下离开（揭开 560ms）→ 新页标题从反方向逐字归位。整段约 1.2 秒，期间禁止重复触发。

   > **必须读作一次连续下扫。** 覆盖与揭开是同一块幕布的两段位移，**中间不能有停顿**，否则会被看成"动了两次"。做法：两段首尾相接（540ms 时换页、560ms 时开始揭开），并使用互补缓动——覆盖用 `cubic-bezier(.4,0,.2,1)`（快入慢停），揭开用 `cubic-bezier(.8,0,.85,.55)`（慢起快走），拼起来像一次有重力的下扫。此外每次切换前会把幕布**无动画地复位到画面上方**，保证方向永远一致。依据见 [04-reference-motion-study.md](./04-reference-motion-study.md)。

   > **换页时必须把窗口滚动重置到顶部。** 首屏文案有一条"按滚动进度淡出"的规则（`.hero-copy` 的 `opacity` 由 `--sp` 驱动）。页面切换时若不重置滚动位置，从关于页 / 项目页这类长页面切回首页，`--sp` 仍是大值，**新页的标题会一直停在淡出状态，看起来就像"文字消失"**。做法：在幕布完全覆盖的那一帧调用 `window.scrollTo(0, 0)` 并立即刷新滚动变量。

   > **切换进行中必须屏蔽滚轮翻页。** 项目页 / 关于页的滚轮换页在触控板上很容易因惯性在切换途中再次触发，表现为"动效播了两次"。做法：两个滚轮处理函数都以 `pageSwitching` 为前提，切换期间直接返回。
5. **滚动特效（E10）**：视口顶部固定一条 1px 进度线；Hero 文案随滚动向上位移并淡出（约 220px 内消失）；背景图形以 5% 比例向下做视差（在**绘制层**偏移，不移动画布本身，避免露出空隙）；`SCROLL` 提示滚动后消失。JS 只写 `--sy` / `--sp` 两个自定义属性。
6. 页面下方留白（约 70vh）后接一行等宽页脚元信息。**不要**再出现"最近更新"这类带边框的卡片区块——该区块已按"与风格不符"的要求移除；后续新增内容需沿用同一套无框、细线、等宽的排版语言。
7. **文章页（ARCHIVE）**：整页背景 = 原子结构（常亮、铺满视口）；**没有标题**，Hero 整块隐藏，只留顶栏与本页独有的竖直列表（规则见 §4.5.2）。
8. **项目页（WORK）**：整页背景 = 线框球；页头收缩、**删除两个按钮**；左侧控制栏 + 右侧分页网格，**滚轮在本页任意位置都翻页**（规则见 §4.5.3）。
9. **关于页（ABOUT）**：整页背景 = 双摆；**页头改成两栏排布**（左标题 / 右说明），**删除两个按钮**；左侧分节轨道 + 右侧分节面板，**滚轮在本页任意位置切换分节**（规则见 §4.5.4）。

| 网格 | `repeat(auto-fill, minmax(300px, 1fr))`，间距 44×52px |
| 翻页动画 | 旧条目朝反方向滑出并淡出（360ms），新条目逐条上移归位（每条 55ms 级联），缓动统一 `cubic-bezier(.86,0,.07,1)`；`prefers-reduced-motion` 下直接切换、不做动画 |
| 滚轮 | **在项目页任意位置**滚轮都翻页（不再限定指针必须在列表上）；780ms 节流，一次手势只翻一页；`ctrl+wheel`（缩放）不拦截；**到首页或末页时不拦截**，交还给页面滚动，避免被困在页内 |
| 触屏与窄屏 | 滚轮不可用，靠**页码按钮**翻页 |
| 空状态 | 无项目时显示：**暂无项目喵～正在努力学习** |

> **索引栏的差异化**（用户要求"相似但不要完全一样"）：文章页索引 = 搜索框 + 标签（带计数）；项目页索引 = 每页数量 + 页码 + 技术栈（不带计数、不带搜索）。

#### 4.5.4 关于页（分节一页式）

**2026-09-29 重写（v2，现行方案）**：本页曾用"折叠共享页头 + 轨道位移 + 固定定位分节导航 + 自定义滚轮"实现，机制过多且无法稳定验证，实测出现 **标题不可见** 与 **切换动效重复** 两个问题。

**v2 结构（最简，且每一项都可预测）**：

1. **首屏就是共享页头**——标题用的正是其他页面同一个 `.hero-copy h1` 元素，因此不可能"消失"；本页只覆盖它的高度（`min-height: 100vh`）、内边距与"取消滚动淡出"（`opacity: 1; transform: none`）。
2. 之后 **4 节各占一屏**（`.asection { min-height: 100vh }`），内容依次是 01 简介 / 02 经历 / 03 技能 / 04 联系。
3. **切换交给浏览器原生滚动吸附**：`html.is-about { scroll-snap-type: y mandatory }` + 各屏 `scroll-snap-align: start`。**不再有自定义滚轮处理、不再有轨道位移、不再有固定定位的导航与计数器**——"动效播两次"与"元素定位错位"这两类问题从结构上被消除。
4. 页头保持紧凑、无按钮；字号与内边距全部走 `clamp()` 流体缩放，自动适配任何窗口尺寸。

> 遗留清理项：旧方案的 `.about-slider` / `.about-track` / `.arail` / `.about-count` 相关 CSS 仍留在原型里（约 180 行）未删除，正式搭建时**不要移植**这些规则。

| 元素 | 规范 |
| --- | --- |
| 结构 | **一屏一节**：滑动容器自身 `height: 100vh; overflow: hidden`，内部轨道整体位移 `translate3d(0, -N×100vh, 0)`。共 **5 屏**——**第 1 屏 = 标题**（kicker + 大标题 + 说明 + 背景注释 + 向下滚动提示），之后 01 简介 / 02 经历 / 03 技能 / 04 联系**各占一屏** |
| 页头 | 共享页头在本页**收起为零高**（`height: 0; padding: 0; overflow: visible`），只为了保留那块固定背景画布；标题搬进第一屏。**删除"读文章""联系我"两个按钮** |
| 背景 | 双摆（E12），整页、常亮；画布在本页改为 `position: fixed` 且取消滚动位移，稳定待在整页背后 |
| 分节轨道 | 固定在滑动容器**顶部的一条横向导航**（与文章页 / 项目页的左侧竖栏刻意区分）：`01 简介 / 02 经历 / 03 技能 / 04 联系`，纯文字按钮，每项前面一条短横线，**选中时横线变亮并从 8px 加长到 14px**；**第一屏（标题屏）整条隐藏** |
| 角落计数 | 右下角一行等宽小字 `01 / 05`，标明当前屏与总屏数（总屏数由脚本按实际屏数写入） |
| 各屏内容 | `01 / PROFILE` 正文；`02 / EXPERIENCE` 时间线（年份 + 事由，行间用两头渐隐的线）；`03 / STACK` 分组清单（组名 + 等宽值）；`04 / CONTACT` 联系方式清单 |
| 切换动画 | 轨道整体位移 720ms `cubic-bezier(.86,0,.07,1)`；`prefers-reduced-motion` 下降为瞬时 |
| 滚轮 | **在本页任意位置滚轮都换屏**；760ms 节流，一次手势只切一屏；到第一屏或最后一屏时不拦截，交还给页面滚动 |
| 触屏与窄屏 | 靠顶部的分节按钮跳屏 |

> **要求**：每一屏必须**正好占满一个屏幕**（桌面端即视口高度），换屏是整块内容一起滑动，而不是列表滚动。

### 4.6 版式与响应式

> **硬性要求（2026-09-29 补充）**：网站必须**自动适配各种尺寸的屏幕**——从 320px 宽的手机到超宽显示器，以及横竖屏切换、系统缩放、浏览器缩放。这是一条验收项，不是"有空再做"。

- 容器宽度：正文 `68ch`（阅读舒适区），布局容器 `1200px`，全宽区块无上限但内容对齐。
- 断点：`480 / 768 / 1024 / 1440`，以容器查询（container queries）优先，减少断点耦合。
- 所有间距使用令牌，禁止魔法数字。
- 移动端优先：桌面端的复杂布局（侧边 TOC、双栏）在窄屏自动折叠，**不隐藏关键功能**。

#### 4.6.1 各页在窄屏下的既定行为

| 页面 / 组件 | ≥ 900px | < 900px |
| --- | --- | --- |
| 顶栏导航 | 横排显示 | 折叠为菜单（首版可用极简下拉），**不隐藏入口** |
| 首屏（所有页共用的 Hero） | 单列堆叠，标题与说明左对齐 | 字号按 `clamp()` 缩小，内边距收紧 |
| 文章页 · 索引栏 | 左侧 212px `sticky` | 折到列表上方，标签横向换行 |
| 项目页 · 控制栏 | 左侧 224px `sticky` | 折到网格上方；**滚轮翻页不可用，靠页码按钮** |
| 项目页 · 网格 | `auto-fill minmax(300px,1fr)` | 单列 |
| 关于页 · 一屏一节 | 滑块 `height: 100vh`，顶部横向导航 | 同样一屏一节；靠顶部分节按钮跳屏 |

#### 4.6.2 移动端必须额外处理的几件事

1. **视口高度用 `dvh` 而不是 `vh`**：手机浏览器的地址栏会让 `100vh` 大于可见区域，导致"一屏"内容被裁掉。写法：`height: 100vh;` 后面跟 `height: 100dvh;` 兜底。关于页的滑动容器尤其要注意。
2. **触屏没有滚轮**：所有"滚轮翻页 / 换屏"都必须有等价的按钮入口（项目页的页码、关于页的分节按钮），并且页内翻页的滚轮事件要以指针类型做判断（`e.pointerType` 或 `matchMedia("(hover: none)")`），避免在触屏上误吞手势滚动。
3. **音频/视频自动播放**、悬停才出现的内容、自定义光标一体禁用：用 `@media (hover: none)` 把 `:hover` 效果改为常显或点击态。
4. **点击热区**：粗指针设备上所有可点元素的有效区域 ≥ 44×44px（文字按钮要补内边距，不能只靠小字号）。
5. **画布尺寸**：三块画布都用 `ResizeObserver` 跟随容器；`devicePixelRatio` 上限 2（移动端 1.5），并在横竖屏切换后重新量尺寸。
6. **横向绝不出现滚动条**：任何固定宽度、`100vw`、负外边距的写法都要在 320px 下实测。

#### 4.6.3 验收用的尺寸矩阵

搭建与验收阶段，至少要在下列尺寸各走一遍**每个页面**（可用浏览器设备模拟 + 一台真机）：

| 宽度 | 代表设备 |
| --- | --- |
| 320 / 360 / 390 | 小屏手机（竖屏） |
| 768 | 平板（竖屏） |
| 834 / 1024 | 平板（横屏）/ 小笔记本 |
| 1280 / 1440 | 主流桌面 |
| 1920 / 2560 | 大屏 / 超宽 |

每个尺寸都要确认：无横向滚动、无文字裁切、背景画布铺满且比例正常、导航可达、页内翻页有可用入口。

### 4.7 可访问性红线（与"炫技"直接冲突的三条）

1. **不劫持滚动**：禁止强制接管滚动、禁止禁用 `user-select`，滚动必须保持原生惯性。
2. **不隐藏焦点**：所有可交互元素的焦点环清晰可见，且样式融入主题（霓虹焦点环）。
3. **装饰元素一律 `aria-hidden="true"`**：线条动画画布、粒子等对辅助技术隐藏，并提供 `sr-only` 的等价信息。

正文对比度 ≥ 4.5:1，大号标题 ≥ 3:1。霓虹色只能用于大字号或装饰，绝不用于小号正文。

### 5.2 渲染与加载策略

- **全站静态预渲染（SSG）**，无 SSR 运行时。
- 所有"动态"内容要么在**构建期**抓取固化为 JSON，要么由**轻量客户端脚本**在空闲时加载。
- 岛屿指令优先级：`client:visible` > `client:idle` > `client:load`（尽量避免 load）。
- 招牌视觉（Tier B）在 `DOMContentLoaded` + `requestIdleCallback` 后再动态 `import()`，确保它永远不阻塞渲染。

## 6. 性能预算与实现手段

### 6.1 硬性预算（CI 强制，超预算即失败）

| 指标 | 预算 | 测量方式 |
| --- | --- | --- |
| 首屏 HTML | ≤ 25 KB gzip | 构建产物统计 |
| 首屏 CSS | ≤ 30 KB gzip | 构建产物统计 |
| 首屏 JS | ≤ 40 KB gzip | 构建产物统计（不含 Tier B/C 懒加载 chunk） |
| 字体 | ≤ 120 KB（≤ 2 文件） | 产物统计 |
| 首页首屏总量（含 shader） | ≤ 250 KB | Lighthouse 网络瀑布 |
| Tier B 线条动画 chunk | ≤ 8 KB gzip | size-limit |
| LCP（4G / 中端机） | < 1.5s | Lighthouse CI（local preset 需考虑偏差，同时用真机抽测） |
| CLS | < 0.05 | Lighthouse CI |
| INP | < 100ms | 真机 / CrUX 数据 |
| TBT | < 200ms | Lighthouse CI |
| Lighthouse | 性能/可访问性/最佳实践/SEO 均 ≥ 95 | CI 门禁 |

### 6.2 具体优化手段（按影响力排序）

1. **默认零 JS**：只有需要交互的组件才挂载脚本；Markdown 内容永不带 JS。
2. **字体**：中文走系统栈，拉丁字体子集化 + preload + swap（省下数 MB）。
3. **CSS**：关键样式内联到 `<head>`，其余按需；Tailwind 按需裁剪；不用大体积 UI 框架。
4. **图片**：一律 `astro:assets` 输出 AVIF/WebP + `width/height` 显式声明 + `loading="lazy"` + `decoding="async"`；首屏 hero 图 `fetchpriority="high"` 并预加载。
5. **第三方脚本**：全部延后到用户交互或滚动到可视区（giscus、统计脚本）；任何第三方脚本体积 > 10 KB 需在 ADR 中说明理由。
6. **动效**：只用 `transform` 与 `opacity`（触发合成层），禁止对 `width/height/top/left` 做动画；使用 CSS `will-change` 要克制。
7. **长列表**：`content-visibility: auto` + `contain-intrinsic-size`。
8. **缓存**：Astro 输出带 hash 的静态资源，可安全设置长效缓存；HTML 短缓存保证更新可见。
9. **预连接/预取**：仅对最高价值的目标（如首篇文章）做 `<link rel="prefetch">`，克制使用。

### 6.3 质量门禁（GitHub Actions）

- `astro check`（类型与内容校验）+ ESLint/Prettier + Stylelint。
- `size-limit` 检查首屏 JS/CSS 体积。
- `@lhci/cli` 对首页、文章列表、文章详情三个 URL 跑 Lighthouse，低于阈值失败。
- 链接检查（内部死链必须为 0，外链失效告警）。
- 可访问性：`axe` 自动化扫描。
- 构建时间纳入观察（目标 < 90s），避免长期膨胀。

## 7. 可访问性与健壮性

- 语义化 HTML5 结构（`header/nav/main/article/aside/footer`）+ 每页唯一 `h1`。
- 全站键盘可达，`Skip to content` 链接为第一个可聚焦元素。

- 无 JS 时：内容、导航、文章全文必须完全可读（渐进增强的底线）。
- 打印样式：文章页提供干净的打印样式（长期维护站点常被忽略的细节）。

## 10. 长期维护机制

### 10.1 内容流程

1. `pnpm new:post "标题"` → 生成带正确 frontmatter 的 Markdown 模板（含日期、草稿标记、标签占位）。
2. 本地 `pnpm dev` 预览 → `pnpm build` 本地校验。
3. 提交并推送 → CI 校验通过 → 自动部署。**主线不直接推，走 PR + 预览构建（可选）**。

### 10.2 代码与文档治理

- 每次重要技术决策写一条 ADR（`docs/adr/NNNN-标题.md`），例如为什么选 Astro、为什么不用 three.js。
- 本套文档随实现同步更新；新会话接手时先读 `docs/README.md`。
- 组件保持"单一职责 + 有类型 props"，鼓励复制粘贴而非过早抽象。
- 依赖最小化是最高优先级：每次新增依赖前先问"能否 30 行原生代码解决"。

### 10.3 自动化

| 工作流 | 触发 | 作用 |
| --- | --- | --- |
| `deploy.yml` | push 到 `main` | 构建 + 部署到 GitHub Pages |
| `quality.yml` | PR / push | 类型检查、Lint、体积预算、Lighthouse、链接检查 |
| `scheduled-refresh.yml` | 每日定时 | 刷新 GitHub 动态数据、处理计划发布文章 |
| Dependabot | 每周 | 依赖更新 PR，附 CI 结果 |

### 10.4 维护日历

- **每月**：合并依赖更新、跑一次 Lighthouse 基线对比、至少发布一篇内容、检查死链。
- **每季**：视觉/交互一次小迭代、检查统计与搜索质量、确认备份可用。
- **每年**：框架大版本升级评估、域名与证书检查、性能重新定基线、回顾设计是否"过时"。

### 10.5 备份与可迁移性

- 内容是最重要的资产：全部在 Git 中，随仓库天然多副本。
- 避免使用专有内容格式（不锁死 CMS）；Markdown + 标准 frontmatter 可迁移到任何静态框架。
- 每个季度在本地完整跑一次 `pnpm build`，确认长期可构建（防止"只在 CI 上能跑"的隐性腐化）。

## 11. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 炫技导致性能与可访问性崩塌 | 违背核心约束 | 性能预算 CI 门禁 + reduced-motion 降级 + 对比度红线 |
| 线条动画在低端机掉帧或耗电 | 用户体验下降、滚动卡顿 | 降低线数/粒子数 + `devicePixelRatio` 上限 + 失焦暂停 + 静态帧降级 |
| GitHub Pages 无后端，评论/搜索/统计受限 | 功能缺口 | 全部选用静态/第三方无后端方案（§5.4） |
| 项目仓库使用 project site 导致资源路径带前缀 | 构建产物 404 | 优先 `<user>.github.io` 用户站仓库；若用项目站则统一配置 `base` 并避免绝对路径 |
| 长期失修、依赖腐化 | 无法构建 | 依赖最小化 + 锁定版本 + Dependabot + 每年季度性构建验证 |
| 中文字体拖慢首屏 | 直接违背轻量目标 | 中文系统字体栈，禁止自托管全量中文字体 |
| 设计反复重做 | 工期失控 | 先锁定"设计令牌 + 骨架"，视觉只在令牌层调整 |
| 内容写得少、站点变"标本" | 与长期维护目标背离 | Now 页 + 每月一篇的节奏 + 首页展示"最近更新"信号 |

## 12. 里程碑计划

| 阶段 | 目标 | 交付物 | 验收标准 | 预估 |
| --- | --- | --- | --- | --- |
| **P0 通路打通** | 证明"提交 → 自动上线"这条链路可用 | 仓库、Astro 脚手架、`deploy.yml`、Pages 配置 | 推送后线上访问到站点；页面标题正确；无 404 资源 | 0.5 天 |
| **P1 设计系统与骨架** | 锁定视觉语言，之后不再返工 | 设计令牌、字体方案、布局壳、导航/页脚、404、暗/亮主题 | 桌面与移动端骨架一致；键盘可达；对比度达标；令牌全覆盖 | 1 天 |
| **P2 内容系统** | 让"写文章"这件事变得无脑 | content collections、列表/详情页、TOC、标签、RSS、sitemap、Pagefind 搜索、OG 图、`new:post` 脚本 | 新增一个 md → 推送 → 自动出现在线上列表并可被搜索 | 1–1.5 天 |
| **P3 招牌视觉** | 落地"硬核/炫技"的核心体验 | Tier A 全套、Hero 线条动画（E1–E5 选定形态）+ 降级链路、页面过渡、命令面板 `⌘K`、极简排版细节 | 低端/省流量/reduced-motion 下自动降级且无报错；Lighthouse 首页 ≥ 90 | 1.5–2 天 |
| **P4 打磨与门禁** | 把质量变成自动化 | Lighthouse CI、size-limit、链接检查、axe 扫描、多浏览器与真机测试、打印样式 | CI 全绿；真机与模拟指标达标；四个浏览器版本无布局破损 | 0.5–1 天 |
| **P5 维护机制** | 让一年后的自己（或另一个会话）能继续做下去 | 文档补齐、ADR、定时刷新工作流、Dependabot、维护日历 | 不看代码即可发文；另一个会话能凭 `docs/` 独立完成一次迭代 | 0.5 天 |

总计约 **5–6 个工作日**（按每日 4–6 小时有效投入估算）。P0-P2 结束后站点已可对外；P3 是风格落地；P4-P5 是长期性的保险。
