# 0014 · 多页静态站上的页面切换动效（E9）

状态：已采纳（2026-09-30，P3）

## 背景

参考站（jiejoe / wodniack / cosmicbroth）都是单页应用，切换只改路由不换文档。
本项目是**多页静态站**，每次切换都是真实的文档跳转，所以"幕布扫过 → 换页 →
揭开"这条时间线要跨两次页面加载才能接上。

## 决策

- **幕布是常驻静态 DOM**（`#curtain`），JS 只切 `is-cover` / `is-pass` / `no-anim` 三个类。
- **离开页**：拦下站内链接（同源、左键、无修饰键、非 `target=_blank`、非 `download`、
  非同页锚点）→ 标题逐字飞出 → 幕布自上而下覆盖 → **540ms 后跳转**。
- **到达页**：`<head>` 里的内联脚本读 `sessionStorage` 的一次性标记，给 `<html>`
  挂 `is-arriving`。CSS 让幕布在这个类存在时**首帧就盖满画面**，所以不会出现
  "先看到新页面、再拉幕布"的闪帧；随后幕布继续向下离开（560ms），新页标题
  从反方向逐字归位。
- **时序与缓动**取自 `04-reference-motion-study.md` §4：覆盖 520ms
  `cubic-bezier(.4,0,.2,1)`（快入慢停），揭开 560ms `cubic-bezier(.8,0,.85,.55)`
  （慢起快走），两段首尾相接。
- **每次切换前把幕布无动画复位**到画面上方，保证方向永远一致。
- **换页一律回到顶部**（并关闭浏览器的滚动恢复），否则首屏文案会停在"淡出"状态，
  看起来像标题消失（§10 第 3 条坑）。
- **切换期间不做任何页内拦截**：项目页的滚轮翻页在 `is-transitioning` 期间直接返回，
  避免触控板惯性触发第二次动效（§10 第 4 条坑）。
- 隐私模式写不进 `sessionStorage` 时退化成普通跳转，功能不受影响。

## 影响

- 站内跳转有约 1.1 秒的仪式感；直接打开链接、刷新、从外部进入时只有进场遮罩。
- 外链、下载链接、页内锚点（文章目录、关于页分节导航）都不播动效。
- 想关掉：`src/config/site.ts` 的 `features.pageTransition` 改成 `false`。

## 上线后的修复记录（2026-09-30，实测发现三个真 bug）

站点上线后用户反馈："切换页面时**有时不播动效**，而且**动效结束后幕布又出现了一次**"。
三个根因都出在实现细节上，均已修复并复验：

1. **到达页没有注册点击拦截。** 早期版本在"到达分支"里直接 `return`，
   于是从刚跳过去的那一页再点导航就退化成普通跳转 —— 表现为动效"一次播、一次不播"。
   现在到达页处理完动画后继续注册拦截器。
2. **收尾时复位幕布，被看见了。** 早期版本在动画结束时 `remove("is-pass")`，
   幕布于是带着过渡从视口下方**动画回到上方**，正好穿过整个画面 ——
   就是用户看到的"动效结束后幕布又出现"。现在收尾只解除 `is-transitioning`，
   幕布停在视口下方；复位只在下一次切换开始时用 `no-anim` 完成（始终在画面外）。
3. **首帧覆盖不能交给 JS。** 注释里写着"CSS 保证首帧幕布盖满画面"，
   但那条规则当时根本没写；P4 把脚本改成外部文件后，脚本执行可能晚于首次绘制，
   于是会先闪一下新页面。现在 `html.is-arriving #curtain { transform: none }`
   写在 `motion.css` 里，JS 只负责下一帧释放它。

顺带补了两处健壮性：后退回到 bfcache 页面时复位状态（否则那一页永远停在"切换中"，
再也不播动效）；跳转意外没发生时有 4 秒兜底复位。
另外把"点当前页自己的链接"改为平滑回到顶部（与原型里点左上角图标的行为一致）。

复验方式：连续点击 首页 → 文章 → 项目 → 关于 → 首页，五次全部触发动效；
采样幕布位移得到 62 → 124 → 257 → 519 → 1046px 的连续曲线（慢起快走），
落地两秒后仍停在 1046px 不动，控制台 0 报错。

## 第二次修复：幕布改由 CSS 动画驱动（2026-09-30 晚）

用户反馈"第一次切换正常，再次进入同一页面时又会闪一下"。根因是同一个坑的第二种表现：

**幕布原来用 CSS transition 位移。** transition 只有在"起始状态已经被浏览器提交过"
时才会播放；而本项目里"加类"与"新文档首次出现"经常落在同一帧 ——
资源全命中缓存时，脚本跑得比首次绘制还早，于是"盖满画面"这一帧从未被提交，
揭开那一下就被跳过、幕布瞬间跳到画面外；新的页面于是硬生生地出现，看起来就是闪一下。
（首次访问时资源还要下载，浏览器已经画过遮盖帧，所以第一次是正常的。）

**处理**：`curtain-cover` / `curtain-pass` 两段都改成 `@keyframes` 动画
（动画永远从第一帧开始播，不依赖初始状态是否被提交），`no-anim` 复位时同时
清掉 animation。实测连续三次进入同一页面，幕布位移曲线完全一致
（14 → 36 → 71 → 127 → 224 → 383 → 646 → 720）。

**教训（同类问题在本项目出现过三次）**：只要"元素出现"与"状态切换"可能同帧发生，
就用 **animation** 而不是 **transition** —— 逐字显影、开机遮罩、幕布揭开都栽在这一点上。
