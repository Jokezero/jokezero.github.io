# 0015 · 动效的降级策略与首屏预算

状态：已采纳（2026-09-30，P3）

## 背景

P3 的验收标准里有三条硬指标：低端机 / 省流量 / `prefers-reduced-motion` 下自动降级
且不报错；首屏 JS ≤ 40 KB（不含懒加载 chunk）；无 JS 时全站仍可完整阅读。

## 决策

**降级触发条件（都指向"静态一帧"）**

| 条件 | 处理 |
| --- | --- |
| `prefers-reduced-motion: reduce` | 只画一帧静态画面，不启动循环；幕布与逐字动画在 CSS 里压成 1ms；进场遮罩不播 |
| `navigator.connection.saveData` 或 `effectiveType` 为 2g/3g | 同上：静态一帧 |
| 无 Canvas 2D / 取不到上下文 | 直接返回，页面保持纯黑，正文照常阅读 |
| 持续帧率低于 26 fps | 自动退回静态帧（保留最后一帧），不再排新的 rAF |
| 页面切到后台（`visibilitychange`） | 暂停渲染循环，回前台再继续 |
| 画布尺寸变化 | `ResizeObserver` 重新量尺寸并重绘一帧 |

**尺寸与清晰度**：`devicePixelRatio` 上限 2，粗指针设备（触屏）上限 1.5；
触屏同时减少线数（纬线 8→6、经线 12→8、轨迹分段 10→8）。

**关于"省流量时跳过下载"**：四个模拟是**静态导入**的，字节数在构建期就定了，
所以省流量模式省下的是**计算**而不是下载。换来的是首屏 5.6–8.1 KB 的内联脚本
（远低于 40 KB 预算）。之所以不用动态 `import()`：Astro 会把体积小的客户端脚本
内联进 HTML，而内联后经过打包器包装的动态 import 会引用只存在于独立文件里的
`__VITE_PRELOAD__` 变量，直接报错（实测踩过两次，见 ADR-0011）。

**无 JS**：画布、幕布、遮罩都只是装饰层；正文与导航全部是构建期渲染的真实 HTML，
没有任何内容是 JS 生成的，CSS 里也没有"默认隐藏、等 JS 显示"的写法。

## 实测（2026-09-30，本地构建）

| 页面 | 内联首屏 JS | 页面 HTML 总计 |
| --- | --- | --- |
| `/` | 5.62 KB | 15.72 KB |
| `/blog/` | 7.09 KB | 16.85 KB |
| `/projects/` | 8.08 KB | 19.08 KB |
| `/about/` | 6.57 KB | 21.18 KB |

- 四页控制台均无报错与警告
- 首页画布平均亮度 9.4/255、文章页 0.65/255、项目页 5.2/255、关于页 1.5/255，
  背景确实"低亮度、不抢正文"
- 页面切换实测：点顶栏"文章" → 幕布下扫（`is-transitioning` + 文案 `LOADING · ARCHIVE`）
  → 跳转 → 新页幕布继续离开 → 原子背景就位 → 滚动位置归零
