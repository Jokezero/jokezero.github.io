# 0005 · P0 的交付边界、占位内容与功能开关默认值

状态：已采纳（2026-09-30，P0）

## 背景

P0 的验收标准只有三条（本地能构建、推送后能上线、打开首页标题为 `zeroweb`、无 404 资源）。
但有几处必须当场做决定：首页长什么样、导航与页脚要不要先做、
`src/config/site.ts` 的 `features` 开关默认值、以及内容集合要不要先建。

## 决策

1. **只交付最小首页**：纯黑底 + 站点名 + 一句说明 + 一行等宽阶段标注。
   顶栏、页脚、主题切换、404 页、设计令牌、字体策略全部留到 P1（与 §0.5 的 P1 施工单一致）。
2. **先建 `src/config/site.ts`**，因为 P0 的 `<title>`、canonical、RSS 元信息都要读它；
   P1 只在其上扩展，不重写。
3. **内容集合先建、内容为空**：`posts` / `projects` / `pages` 的 schema 按
   `01-design-spec.md` §3.2 落地。构建时会打印 `glob-loader` 的"目录为空"警告，这是预期行为，
   P2 放入第一篇内容后消失。
4. **`features` 初始值全部关闭**（动效用 `static`、评论/搜索/统计为 `false`）：
   它们分别在 P2、P3 落地，默认关闭可保证任何阶段都不加载第三方脚本。
5. **RSS 先建端点**（`/rss.xml`），先输出站点元信息；全文渲染与 OG 图在 P2 补齐。
   `robots.txt`、`404`、`/blog` 等路由按施工单留在 P1/P2。
6. **首页与站点描述为占位文案**（对应 `03-open-questions.md` 的 A6 / B12）：
   现在的"个人网站 —— 技术长文、项目记录与长期维护日志"是通用占位，
   待你给出真实定位后只需改 `src/config/site.ts` 一处。

## 影响

- P0 交付物可验证、可回滚，且不会把 P1/P2 的工作提前做歪。
- 站点描述与首页文案属于"待你补的真实内容"，不是最终定稿。
