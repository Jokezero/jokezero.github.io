# 0013 · 四套背景模拟的画布形态

状态：已采纳（2026-09-30，P3）

## 背景

规范里关于"背景画布放在哪里"有两处不完全一致的描述：

- `01-design-spec.md` §4.5.1 提到两块画布：`#scene` 在**首屏内部**（随滚动压暗，服务首页/项目页/关于页），`#listScene` 用 `position: fixed` **铺满视口**（服务文章页）。
- 同一节与 §4.5.3 / §4.5.4 又说项目页、关于页都是"整页、常亮"的背景。

另外 §4.5.2 里有一句"首屏背景的三体运动**完全不响应鼠标**"，与 §4.5 的 E13
（"当前页面的整套模拟跟随指针平移"）冲突。

## 决策

1. **首页 = 首屏内画布**（`absolute` + 容器 `overflow: hidden`）：随首屏一起滚走、
   随滚动压暗到 22%、做 5% 的向下视差。理由：三体是"第一页的背景"，
   滚动特效（E10）本来就是围绕首屏设计的。
2. **文章列表 / 项目列表 / 关于页 = 整页固定画布**（`fixed inset-0`）：常亮、铺满视口。
3. **一页只放一个主体**：`/` 三体、`/blog` 与 `/tags/*` 原子、`/projects` 线框球、
   `/about` 双摆。文章详情页与项目详情页**不放任何画布**（`07-layout-post-project.md`
   §1 的"阅读页不放动效背景"是硬约束，性能与可读性都更优）。
4. **鼠标视差对所有背景生效**（以 E13 为准），上限横向 ±27px、纵向 ±12px，
   指针离开后约 1 秒归零；只在绘制层叠加偏移，不改动模拟本身的状态与轨迹。
5. 内容层一律 `position: relative; z-index: 2`（`<main>`、页脚、关于页各分节）。
   这是 `02-build-and-deploy.md` §10 第 2 条坑，不做就会被背景盖住。

## 影响

- 四页观感统一（纯黑底 + 单色细线 + 低亮度），但背景各不相同。
- 首页背景随滚动离开视线，列表页背景一直待命 —— 正好对应两种阅读场景。
- 想一键回到纯黑：把 `src/config/site.ts` 的 `features.heroEffect` 改成 `"static"`。

## 与原型的两处刻意不同

1. **首屏高度取满屏（`100dvh`），不加"页面下方约 70vh 留白"**（§4.5.1 第 6 条）。
   原型是一张单页 demo，那块留白是它的收尾；本站有真实的页脚（社交链接 + 构建戳），
   再垫 70vh 空白只会让手机用户多滑一屏。留白改为页脚自带的 `mt-24`。
2. **亮色主题用一行 CSS 反转画布**（`filter: invert(1)`）而不是写第二套配色：
   画布底色透明、线条统一用白色绘制，亮色主题下整体反转成黑线白底，
   与"亮色不是反转"的令牌策略并不冲突（令牌已经单独校准过）。
