# 0011 · 全文搜索用 Pagefind，入口放在页脚与文章索引栏

状态：已采纳（2026-09-30，P2）

## 背景

`01-design-spec.md` §4.5.1 明确"右上角不放任何按钮（⌘K 与订阅按钮已移除）"，
但 §2.2 又提到全局搜索快捷键。两者冲突时以"顶栏不放按钮"的视觉结论为准，
那么搜索入口放哪里、以及它和文章列表里那个搜索框是什么关系，需要定下来。

## 决策

- **两种搜索各司其职**：
  - 文章列表的搜索框 = 在当前列表里**按标题**快速过滤（纯前端、即时、无请求）；
  - `/search` 页 = **全站全文搜索**（Pagefind 索引正文），入口放在**页脚**，
    文章列表的索引栏与 404 页也各有入口。
- 索引在 `pnpm build` 里生成（`astro build && pagefind --site dist`），
  产物是纯静态文件；浏览器只在用户**开始输入后**才加载 `pagefind.js`。
- 本地 `pnpm dev` 没有索引，搜索页会明确提示"构建后可用"，不静默失败。
- 页脚只放"文章 / 项目 / 搜索"三个站内入口。**RSS 刻意不放**：
  `06-content-model.md` §6 已确认界面不提供 RSS 入口，只在 `<head>` 保留自动发现标记。

## 踩坑记录（实测）

**加载 Pagefind 的脚本必须用 `is:inline`。** Astro 会把体积小的客户端脚本内联进
HTML，而经过 Vite 转译的动态 `import()` 会引用只存在于独立脚本文件里的
`__VITE_PRELOAD__` 变量，内联后直接 `ReferenceError`（本轮实测踩到，表现为
搜索永远返回空结果）。所以 `/search` 用原生内联脚本 + 原生动态 import，
并保留 `console.warn` 便于以后排查。

## 影响

- 顶栏维持"无按钮"，符合 §4.5.1；搜索仍有两个稳定入口。
- 中文分词：Pagefind 对 `zh-cn` 不做词干还原（构建时会打印一句 note），
  实测"日志"能同时命中文章与项目，够用。
