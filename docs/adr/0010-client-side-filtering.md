# 0010 · 筛选、排序与分页放在客户端

状态：已采纳（2026-09-30，P2）

## 背景

文章列表要"多标签 OR + 命中数排序 + 标签计数动态重算"，项目列表还叠加
"每页数量 / 页码 / 命中数排序后页码归零"。这些状态组合没有对应的 URL，
做成服务端渲染要为每种组合生成页面（组合爆炸），而且静态站每次筛选都整页刷新。

## 决策

- **构建期把全部条目渲染成真实 HTML**（带 `data-tags` / `data-date` / `data-title`）：
  无 JS 也能读到完整列表、Pagefind 能索引、SEO 与首屏速度都不受影响。
- **JS 只做三件事**：筛选（OR）、排序（命中标签数 → 日期 → 标题）、切换空状态与分页。
  普通 TypeScript 客户端脚本，不引任何框架。
- 排序规则与 `06-content-model.md` §4 完全一致，文章页与项目页共用同一套判断。
- 项目页的"每页数量 / 页码"是纯展示状态，**不写进 URL**：
  书签不保留筛选结果，换来干净的地址。要分享筛选结果需要重新点一次。

## 影响

- 数据量涨到几百条时，客户端排序仍只是一次数组排序，没有性能问题；
  真到上千条再考虑把分页静态化。
- 若以后要把筛选状态放进 URL（可分享），改成读取 `?tags=a,b` 即可，渲染逻辑不动。
