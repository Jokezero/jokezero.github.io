# 0019 · 站内导航改为"不换文档"的 SPA 式切换

状态：已采纳（2026-10-01）· 取代 [0014](./0014-transition-on-static-site.md) 的跨文档实现

## 背景

多页站点（MPA）每次站内跳转都要**更换文档**。浏览器在"旧文档已丢弃、新文档还没画出来"
的那一瞬间会铺自己的底色 —— Firefox 默认是白色。用户做了对照实验确认了这一点：
把浏览器背景设成白色、网页是黑底时，那一闪极其刺眼；而把浏览器背景设成黑色时几乎看不见。

时间线也对得上：点击 → 幕布下扫（520ms）→ `location.href` → **约 260ms 后**
浏览器切换文档 → 白闪 → 新文档首帧（盖着幕布）→ 幕布继续落下。
用户看到的正是"进度条走到最后 1/10 时闪一下"（进度条 760ms 动画，90% ≈ 800ms）。

之前几轮的修复（黑遮罩、body 首位、内联关键样式、`fill-mode: both`）都只能解决**文档内部**
的问题，而这个空档在**文档外面**。唯一能盖住它的机制是跨文档 View Transitions
（`@view-transition { navigation: auto }`），但用户浏览器实测
`CSS.supports("@view-transition { navigation: auto; }")` 返回 **false** —— 不支持。

## 决策

**站内导航不再更换文档。** 点击站内链接时：幕布下扫（520ms，同时并行 `fetch` 新页面）
→ 在幕布完全覆盖期间把新页面的内容搬进当前文档 → 重新挂载该页行为 → 幕布落下（560ms）。

### 关键设计

1. **唯一客户端入口** `src/scripts/app.ts`：所有页面行为被拆成可重复挂载的 `initX()`，
   换页后由 `mountPage()` 统一重新挂载；需要收尾的（全局监听、观察器、动画循环）
   返回一个销毁函数，换页前统一调用。
2. **常驻层跨页面存活**：幕布 `#curtain`、开机遮罩 `#boot`、进度线 `#scroll-progress`
   在换页时先摘出来，替换完内容再放回 `<body>` 最前面 —— 幕布因此永远待在同一份文档里，
   结构上不可能再出现"文档之间"的空档。
3. **时序不再依赖加载速度**：内容替换发生在幕布完全覆盖期间，所以"新页面多快加载完"
   完全不影响观感（这也顺带修掉了"第二次进入同一页动效变短"的问题）。
4. **样式表跟着换**：新页面用到的 CSS 补进来、不再需要的摘掉，并且**等新样式表加载完才揭幕**，
   避免露出未样式化的内容。
5. **head 元信息跟着换**：标题、描述、canonical、OG 标签。
6. **前进/后退**：`popstate` 同样走换内容（不带幕布动画），URL 与内容保持一致。
7. **无障碍**：换页后把焦点移到 `<main tabindex="-1">`，并更新 `document.title`，
   屏幕阅读器能感知"换页了"。
8. **渐进增强**：没有 JS 时链接就是普通链接，整页跳转照旧可用。顺带修掉一个既有缺陷 ——
   无 JS 时开机遮罩会永久盖住页面（现在有 `<noscript>` 兜底把它关掉）。
9. **失败兜底**：`fetch` 失败（断网、404 等）时写入一次性标记后 `location.assign()`
   退回整页跳转，到达页仍会播放揭幕动画。

## 代价与取舍

- **站内跳转不再触发完整文档加载** → 统计脚本（如将来启用 Umami / Cloudflare）只在首次加载记账；
  要精确统计站内浏览，将来需在换页时手动上报（当前统计是关闭的，先记录在案）。
- 每次换页会重建该页的初始化（背景模拟、观察器等）。换来的是"每页行为完全一致"，
  代价是可忽略的重建开销（实测切换后控制台无报错、动效与筛选均正常）。
- 首屏 JS 略增，实测全站 JS 合计 10.4 KB gzip（预算 40 KB）。

## 实测（2026-10-01，本机 Chromium）

- 连续四次切换（含**第二次**进入同一页）幕布位移轨迹完全一致：
  `-26 → 0 → 24 → 118 → 425 → 720`，落地后静止不动。
- `documentElement.dataset.spa = "true"` 证明全程没有重新加载文档；控制台 0 报错。
- 详情页功能复验：多标签筛选（OR + 命中数排序）、灯箱开关、代码复制工具条、文章目录、
  项目分页与每页数量、外链属性、全文搜索、关于页滚动吸附 —— 全部正常。
- 尺寸矩阵复查 36 项（6 宽度 × 6 页面）0 问题；窄屏 MENU 面板开合后经 SPA 跳转正常。

## 追加修复（2026-10-01 当日，用户实测反馈）

1. **动效被连续触发两次** —— 根因是重构时把常驻层（幕布等）**摘下来又插回去**：
   重新插入 DOM 会让元素身上的 CSS 动画从头再播一遍，于是"覆盖"重播一次、接着才是"揭开"。
   现在改成**只替换其余节点、常驻层原地不动**（并跳过新内容里的同名副本）。
   实测单次点击的幕布轨迹只有一个方向变化（`-84 → -21 → -1 → 2 → … → 455 → 720` 后静止）。
2. **手机上关于页滚不到页脚** —— `scroll-snap-type: y mandatory` 会把滚动死死拽回分节起点，
   最末一节之后的页脚**永远看不到**，手指滑动还被反复弹回（也因此"顶部分节导航像是消失了"，
   因为根本滑不到分节）。改成 `proximity`，并在触屏（`hover: none`）上**完全关闭吸附** ——
   移动端本来就该用顶部的分节按钮跳屏。实测手机尺寸下 `scrollY` 能到达 `maxScroll`、页脚可见。
3. **右下角计数压住页脚** —— 关于页固定在右下角的 `0N / 04` 在滚到页脚时会正好盖住
   版本号与链接（手机上尤其明显）。现在页脚进入视口即隐藏该计数。
4. **页脚版本号挪到与版权同一行**（右列只留站内链接）：窄屏上文字被放大/换行时，
  版本号不会再孤零零掉到下一行、看起来像"多出来的一块"。

### 第二轮追加修复（同日，用户复测）

5. **首屏标题不再渐隐、而是一滚就没** —— 根因同样是"缓存了旧引用"：
   滚动特效脚本在初始化时把 `[data-hero]` 元素存了下来，SPA 换页后那个节点已被替换，
   于是 `offsetHeight` 读到 0、滚动进度瞬间顶到最大值、`opacity` 直接归零。
   现在每次读取滚动量都重新查一次首屏元素。
6. **关于页的吸附动效不能用 proximity 顶替 mandatory** —— 上一轮为了修手机端，
   把桌面也改成了就近吸附，结果"一屏一节"的干脆手感没了。现在桌面保持 `mandatory`，
   只在触屏（`hover: none`）上关掉吸附。
7. **强制吸附会让页脚永远够不到**（桌面也一样）：滚动只会停在最后一个分节，
   页脚被留在视口下方。现在给页脚加了 `scroll-snap-align: end`，
   页面末端成为一个合法停靠点 —— 实测 `scrollY` 能到达 `maxScroll`、页脚完整可见、链接可点。
8. **页脚版本号挪回右下角**（与站内链接同列），恢复重构前的排布。
9. **手机端关于页不再强行"一屏一节"**：手机可视高度小，顶部还压着顶栏 + 分节导航
   （约 100px），每节再撑满整屏会让滚动又长又别扭。现在触屏（`hover: none`）下内容按自然高度
   排布、节间恢复正常间距（首屏标题仍占满整屏），分节导航与计数照旧可用；
   **桌面端的规则完全没动**（仍在 media query 之外，实测吸附类型、分节高度、页脚可达性均与改动前一致）。

### 与重构前的逐项对比（2026-10-01）

把 `pre-spa` 标签那一版构造成对照站点，用同一套测量脚本在 390 / 1280 两个宽度、
6 个页面上逐项比对：**顶栏高度、导航与菜单的显示状态、正文首个元素的位置、
页脚位置、页脚左右两栏文案、滚动吸附类型 —— 全部一致**，
唯一差异是版本号本身（`v2026.10.0.0` → `v2026.10.0.4`，因为提交数变了）。
