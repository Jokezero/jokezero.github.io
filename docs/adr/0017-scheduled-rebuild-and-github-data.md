# 0017 · 每日重建、GitHub 动态数据与不做计划发布

状态：已采纳（2026-09-30，P5）

## 背景

`02-build-and-deploy.md` §7 的 P5 清单里有三件事需要定夺：

1. "添加 `scheduled-refresh.yml`（每日定时重建：刷新 GitHub 动态数据 + 发布到期的计划文章）"
2. GitHub 动态数据要不要抓、抓来给谁看（`01-design-spec.md` §5.4 提到 star 数 / 贡献图）
3. 但 `06-content-model.md` 明确写着"**不做**置顶、**不做**计划发布"

## 决策

### 1. 每日重建并入 `deploy.yml`，不新建一个 workflow 文件

给 `deploy.yml` 加一条 `schedule`（每天 03:10 UTC / 北京 11:10）。理由：
新建 `scheduled-refresh.yml` 意味着把 build + upload-artifact + deploy-pages
那十几行**再抄一遍**，两份配置迟早会漂移（比如只改了一边的 Node 版本），
而"部署"这件事只应该有一个事实来源。定时任务与推送共用同一条流水线，
行为完全一致。**如果以后想让定时重建独立失败、不影响推送部署，再拆也不迟。**

### 2. GitHub 动态数据：构建期抓取，缺数据就整块隐藏

- `scripts/fetch-github-data.mjs`：抓本站仓库 + 每个项目 `repo:` 指向的仓库的
  star 数与最近推送时间，写进 `src/data/github.json`（**进仓库**）。
- 没有 `GITHUB_TOKEN` 时**什么都不做**并保留旧数据：本地开发、离线构建都不会因此中断。
- 单个仓库抓取失败只告警、不覆盖旧值，更不会中断构建。
- 渲染侧（`src/lib/github.ts`）在**没有数据时不显示**那一行 —— 不显示 0，
  也不显示占位符。首页状态行会多一段"最近提交 2026.09.30"，
  项目卡片在 star 数 > 0 时多一段 `★ 12`。
- 浏览器端**不调用** GitHub API：访客不承担限流风险（§5.4 的约定）。

### 3. 明确不做计划发布

`06-content-model.md` §2/§6 已经确认"不做计划发布"。因此定时重建只负责
**刷新数据与构建戳**，不会按 `pubDate` 自动放出未来日期的文章：
`src/lib/posts.ts` 只过滤 `draft`，不看日期。想定时发布就自己在那天推送 —— 
这是刻意的取舍（少一个容易出错的机制）。

## 影响

- 首页状态行与项目卡片的数字每天自动更新一次，不需要人工干预。
- 仓库里多一个 `src/data/github.json`；它是**构建期数据快照**，不是手写内容。
- 想彻底关掉：把 `package.json` 的 `build` 脚本里那段 `node scripts/fetch-github-data.mjs &&`
  删掉即可，页面会自动回到"不显示数字"的状态。
